# Android 공유 가져오기 PoC 계획

- 상태: 계획
- 관련 결정: [`ADR 0002`](../../decisions/0002-share-based-track-import.md)
- 결과: 없음

## 검증 질문

지원 대상으로 결정한 음악 앱의 개별 곡 공유 입력을 Android Share Target이 받아 검증·정규화하고, 프로세스 종료 후에도 같은 가져오기를 복구할 수 있는가?

## 선행 조건

- 곡 가져오기 계약 최소안과 지원 URL 형식이 결정되어야 한다.
- 실제 Android 기기에서 실행 가능한 최소 Share Target과 영속 저장 구현이 있어야 한다.

## 범위

- `ACTION_SEND`의 `text/plain` 입력
- 허용된 제공업체의 개별 곡 URL과 지원하지 않는 입력
- 정규화된 제공업체·리소스 ID와 불투명한 `importId` 저장
- 중복 공유, 오프라인, 프로세스 종료 후 복구
- 곡을 특정할 수 없는 입력의 명시적 선택 또는 안전한 거부

구체적인 제공업체별 URL과 상태 전이는 후속 계약에서 정한다.

## 절차 초안

1. 지원 음악 앱에서 개별 곡을 Lymo Share Target으로 공유한다.
2. Lymo가 입력을 검증하고 지속 가능한 가져오기 레코드를 생성하는지 확인한다.
3. 앱 프로세스를 종료한 뒤 컨테이너 앱을 다시 실행한다.
4. 저장된 가져오기를 찾아 같은 곡 식별 절차를 재개하는지 확인한다.
5. 같은 곡을 다시 공유하고 중복 처리 결과를 확인한다.
6. 지원하지 않거나 모호한 입력과 오프라인 상태에서 안전한 오류·복구 흐름을 확인한다.

## 통과 조건

- 허용된 개별 곡 입력만 계약에 따라 정규화된다.
- 원본 URL을 내부 식별자로 사용하지 않고 불투명한 `importId`로 가져오기를 찾는다.
- 프로세스 종료와 재실행 후 가져오기를 복구한다.
- 중복, 오프라인과 모호한 입력을 성공으로 가장하지 않는다.
- 알림 접근이나 재생 관찰 권한 없이 기본 가져오기가 동작한다.

## 기록할 환경과 증거

- 기기 모델, Android 버전, 음악 앱과 Lymo 버전
- 단계별 실제 관찰과 오류·폴백 상태
- 필요할 때만 민감 정보가 제거된 스크린샷

이 문서는 계획이며 실제 기기 지원을 증명하지 않는다.
