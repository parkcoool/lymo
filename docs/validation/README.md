# 실제 기기 검증

이 디렉터리는 플랫폼이나 외부 앱이 실제로 보장하는 범위를 확인하기 위한 PoC 계획과
정제된 결과를 관리합니다. 시뮬레이터, 목 테스트와 코드 검토 결과를 실제 기기
증거로 표현하지 않습니다.

## 구조

- [`device-poc-template.md`](device-poc-template.md): 실제 검증 결과를 기록하는 공통 양식
- [`plans/`](plans/): 아직 수행하지 않은 검증의 가설, 절차와 통과 조건
- `results/`: 실제 실행 결과. 첫 결과를 기록할 때 생성

현재 계획:

- [Android 공유 가져오기](plans/android-share-import.md)
- [Android 재생 관찰](plans/android-playback-observation.md)
- [iOS 공유 가져오기](plans/ios-share-import.md)

현재 저장소에는 실제 기기 검증 결과가 없습니다.

## 상태

| 상태 | 의미 |
| --- | --- |
| 계획 | 실행 조건과 절차를 준비하는 중 |
| 진행 중 | 하나 이상의 실제 기기 실행을 수행 중 |
| 통과 | 기록된 환경과 조건에서 통과 조건을 충족 |
| 실패 | 기록된 환경과 조건에서 통과 조건을 충족하지 못함 |
| 차단 | 계정, 기기, 구현 또는 외부 조건이 없어 실행할 수 없음 |
| 재검증 필요 | 이전 결과 이후 관련 OS, 앱, 구현 또는 정책이 바뀜 |

`통과`는 기록된 기기, OS, 외부 앱 버전과 절차에만 적용합니다. 한 번의 성공을 모든
환경의 제품 지원으로 확대하지 않습니다.

## 기록 절차

1. 관련 계획과 계약, ADR의 전제 및 통과 조건을 확인합니다.
2. `device-poc-template.md`를 복사해
   `results/YYYY-MM-DD-<lowercase-kebab-topic>.md`로 저장합니다.
3. 기기 모델, OS, 외부 앱 버전, Lymo 커밋 또는 빌드 식별자와 사전 조건을 적습니다.
4. 예상 결과가 아니라 실제 관찰 내용을 단계별로 기록합니다.
5. 실패, 폴백, 미검증 범위와 재현에 필요한 정제된 증거를 남깁니다.
6. 결과가 현재 지원 범위를 바꾸면 `PROJECT_CONTEXT.md`에는 결론과 결과 문서 링크만
   반영합니다.

같은 검증을 다시 수행할 때 기존 결과를 덮어쓰지 않고 새 날짜의 결과를 추가합니다.
검증에 필요한 최소 실험 프로젝트는 사용할 수 있지만 그 구조를 제품 모듈 구조의
결정이나 재사용 대상으로 간주하지 않습니다.

## 증거와 공개 범위

- 텍스트로 재현 가능한 절차와 관찰 내용을 우선합니다.
- 스크린샷은 결론 입증에 필요하고 민감 정보가 제거된 경우에만 저장합니다.
- 비밀 정보, 계정 정보, 개인·기기 식별자, 전체 공유 URL과 전체 가사를 기록하지
  않습니다.
- 원본 로그와 대용량 화면 녹화는 커밋하지 않습니다. 필요한 사실만 정제해 적습니다.
- 외부 자료를 근거로 사용하면 접근일과 출처를 남기고, 공식 문서와 실제 관찰을
  구분합니다.
