# ADR 0002: 공유 기반 곡 가져오기와 재생 관찰을 분리한다

- 상태: 승인
- 결정일: 2026-09-13
- 관련 문서: [`PROJECT_CONTEXT.md`](../PROJECT_CONTEXT.md), [`AGENTS.md`](../../AGENTS.md)

## 맥락

음악 앱에서 공유한 링크는 곡을 식별하는 입력이 될 수 있지만 현재 재생 위치나
재생·일시정지 상태를 보장하지 않는다. Android와 iOS에서 관찰 가능한 재생 정보도
권한, 소스 앱과 OS 정책에 따라 달라진다. 가져오기와 실시간 연동을 하나의 기능으로
취급하면 지원되지 않는 동작을 제품이 보장하는 것처럼 보일 수 있다.

구체적인 계약 필드, 제공업체별 URL 형식과 보존 정책은 후속 결정으로 남긴다.

## 결정

- 두 플랫폼의 기본 경로를 `음악 앱 → 개별 곡을 Lymo로 공유 → Lymo에서 읽기`로
  정의한다.
- `TrackImport`는 곡을 식별하기 위한 요청이며 `PlaybackCapability`나
  `PlaybackClock`을 제공한다고 간주하지 않는다.
- 모든 읽기 경험은 재생 관찰 기능 없이도 완결되어야 한다.
- 입력에서 곡을 특정할 수 없으면 추측하지 않고 사용자가 선택하게 한다.
- 허용된 제공업체 URL만 검증·정규화하며 공유 수신 컴포넌트에서 임의의 URL을
  가져오지 않는다.
- Android Share Target은 기본 가져오기 경로로 유지하고 재생 관찰과 자동 감지는
  권한과 신뢰 가능한 정보가 있을 때만 제공하는 선택 기능으로 둔다.
- iOS Share Extension은 입력 검증·정규화와 App Group 기반 가져오기 보존까지만
  담당한다. 컨테이너 앱 자동 실행을 가정하지 않는다.

## 검토한 대안

### 자동 재생 감지를 기본 경로로 사용한다

소스 앱, 권한과 OS 정책에 따라 동작이 달라 두 플랫폼에서 신뢰할 수 있는 기본 경험을
보장할 수 없다. 공유 기반 가져오기의 선택 기능으로만 다룬다.

### 공유 입력을 받으면 실시간 가사 동기화가 가능하다고 간주한다

공유 링크에는 신뢰 가능한 재생 시계가 없으므로 채택하지 않았다. 재생 정보가 별도로
검증된 경우에만 실시간 강조를 제공한다.

### 공유 수신 컴포넌트에서 분석까지 완료한다

공유 수신 컴포넌트는 실행 시간과 생명주기가 제한될 수 있고 로그인, 네트워크와 AI
작업의 복구도 어렵다. 장기 작업은 컨테이너 앱이나 서버로 넘긴다.

## 결과

- 공유로 가져오기만 지원되는 환경에서도 일관된 읽기 경험을 제공할 수 있다.
- 재생 관찰 여부에 따라 UI 상태와 폴백을 명시적으로 표현해야 한다.
- 가져오기는 프로세스 종료, 중복 요청과 오프라인 상태에서도 복구 가능해야 한다.
- 공통 계약과 제공업체별 지원 범위는 후속 회의와 검증이 필요하다.

## 검증 방법

- Android 공유 가져오기, Android 재생 관찰, iOS 공유 가져오기 실제 기기 PoC를
  각각 수행한다.
- 기기, OS, 외부 앱 버전, 절차와 결과를 [`validation/`](../validation/)에 기록한다.
- 현재 저장소에는 제품 구현과 실제 기기 검증 결과가 없다.
