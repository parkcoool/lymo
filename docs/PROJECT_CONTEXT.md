이 문서는 현재 방향을 기록하며 제품 불변 조건이 아님. 구현 전에 코드, ADR, 공식 문서, 제공업체 정책과 일치하는지 확인할 것. 제품의 장기 정의는 [`../AGENTS.md`](../AGENTS.md)를 따를 것.

결정되지 않은 사항은 [`OPEN_QUESTIONS.md`](OPEN_QUESTIONS.md)에서 관리할 것.

## 저장소 상태

- 현재 제품 구현 모듈은 없으며 지침과 개발 문서만 구성된 상태.
- Android, iOS, 서버, 공유 계약의 모듈 구조는 미확정 상태.
- 모듈 구조는 첫 프로젝트 생성 전에 ADR로 결정할 것.
- V1 구현은 제품 동작 참고용으로만 사용하고 구조나 코드를 기본 이식하지 않을 것.

## V2 기술 방향

- Android: **Kotlin + Jetpack Compose** 네이티브 앱.
- iOS: **Swift + SwiftUI** 네이티브 앱과 **App Group** 기반 **Share Extension**.
- 플랫폼 UI와 생명주기 코드는 공유하지 않고 API 계약, 픽스처, 도메인 용어, 디자인 토큰만 공유할 것.
- React Native, Expo, Kotlin Multiplatform 등 새 크로스플랫폼 계층은 ADR 승인 후 도입할 것.

## 공통 곡 가져오기 범위

공통 제품 경로: `음악 앱 → 개별 곡을 Lymo로 공유 → Lymo에서 읽기`

- 사용자에게는 두 플랫폼 모두 **공유로 곡 가져오기**로 표현하되, Android는 Share Target, iOS는 Share Extension으로 구현할 것.
- Spotify Track과 Apple Music Song URL부터 지원할 것.
- YouTube Music은 메타데이터와 가사 일치를 별도 검증하는 베타로 취급할 것.
- 앨범과 플레이리스트를 현재 곡으로 추측하지 말고, 지원 시 곡 선택기를 제공할 것.
- 허용된 제공업체 URL만 검증·정규화하고, 영속 저장한 `TrackImport`를 불투명한 `importId`로 처리할 것.
- 공유 입력만으로 재생 위치를 알 수 있다고 가정하지 말고, 모든 가져오기는 실시간 연동 없이도 완결된 읽기 경험을 제공할 것.
- 로그인, 외부 네트워크 요청과 AI 분석은 플랫폼의 공유 수신 컴포넌트가 아니라 앱 또는 서버에서 수행할 것.

## Android 초기 범위

- 기본 경로는 `ACTION_SEND`의 `text/plain`을 받는 Lymo Share Target으로 제공할 것.
- 공유로 가져오기는 알림 접근 권한 없이도 사용할 수 있는 독립적인 진입점으로 유지할 것.
- 사용자 권한 부여 후 지원 앱의 공개 MediaSession/알림 기능만 사용할 것.
- 자동 감지는 공유로 가져오기를 대체하지 않는, 소스 앱에 따라 달라지는 기회적 기능으로 취급할 것.
- 곡과 재생 시간을 신뢰할 수 있을 때만 실시간 가사 강조를 제공할 것.
- 신뢰할 수 없으면 실시간 연동 없는 읽기 방식으로 폴백할 것.

## iOS 초기 범위

기본 경로: `음악 앱 → 개별 곡 공유 → Lymo Share Extension → Lymo에서 읽기`

- Share Extension은 URL 검증·정규화와 `importId` 기반 App Group 저장까지만 수행할 것.
- 화면 이동은 컨테이너 앱에서 수행할 것.
- 컨테이너 앱 자동 실행을 가정하지 말고, 알림 없이도 최근 가져오기를 복구할 것.
- 화면/오디오 캡처와 Shazam 방식 인식은 승인 및 실제 기기 검증을 거친 실험으로만 다룰 것.

## 선행 검증

다음 실제 기기 PoC를 통과하고 기기, OS, 외부 앱 버전, 절차와 결과를 기록할 것.

1. Android 공유 가져오기: 지원 음악 앱이 공유한 개별 곡 URL을 Share Target에서 수신·정규화하고 프로세스 종료 후에도 복구할 것.
2. Android 재생 관찰: 곡 변경, 재생/일시정지, 탐색 위치를 관찰하고 신뢰할 수 없을 때 안전하게 폴백할 것.
3. iOS 공유 가져오기: 공유 URL을 Share Extension에서 App Group 큐에 저장하고 나중에 실행한 컨테이너 앱에서 복구할 것.

현재 저장소에는 완료 증빙이 없음. 시뮬레이터나 목 테스트를 실제 기기 검증으로 표현하지 않을 것.
